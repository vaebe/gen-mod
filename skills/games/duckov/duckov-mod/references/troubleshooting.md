# 排查与用户验收

## 按阶段定位

| 现象 | 先检查 | 能确认的边界 |
| --- | --- | --- |
| prepare 失败 | ReferenceDirectory、最小 DLL 文件组、dotnet 命令路径 | 文件或命令缺失，不等于 API 不支持 |
| 编译类型找不到 | 定义类型的程序集、间接依赖与框架版本 | 编译契约问题，不用空类型替代 |
| 编译成员找不到 | 完整类型名、当前 DLL 签名、重载和可见性 | 网页样例可能与目标版本不同 |
| Mod 菜单中找不到 | 独立子目录、name、DLL 文件名、info.ini、preview.png | 先核对真实目录与元数据，再查日志 |
| 显示但加载失败 | 公开 ModBehaviour、基类、namespace、依赖加载异常 | 编译通过不证明运行依赖齐全 |
| 已加载但功能没变化 | 场景前提、实际入口、事件、目标对象、补丁命中 | 加载日志只证明入口执行 |
| 切场景或重启用后异常 | 引用失效、重复订阅、迟到异步结果、自己资源的清理 | 检查实际生命周期，不先归因游戏 bug |
| Bundle 或额外 DLL 不存在 | package 真实文件集、交付映射、安装目标与资源路径 | 当前 package 脚本不会自动收集这些文件 |

## 日志证据

上游示例给出的 Windows 日志位置是 `%USERPROFILE%/AppData/LocalLow/TeamSoda/Duckov/Player.log`，上一轮为 Player-prev.log；macOS 为 `~/Library/Logs/TeamSoda/Duckov/Player.log`。路径由 [DisplayItemValue 源码](https://github.com/xvrsl/duckov_modding/blob/main/DisplayItemValue/ModBehaviour.cs)提供，实际可用性由用户环境确认。

若用户提供日志，围绕本 Mod 名、异常类型与触发时间读取必要片段。重点保留第一处异常和相关调用栈，区分加载失败、缺依赖、MissingMethodException、TypeLoadException 与业务执行异常。

只加入有定位价值的日志：入口/启用状态、注册失败、目标缺失及必要参数；不每帧输出，也不记录完整存档或无关个人信息。没有日志时提供所需证据，不声称已经在用户游戏中复现。

## 交付说明与验收步骤

只为当前功能列出适用项，由用户执行游戏内验收；不因本技能自动启动游戏或运行测试：

- 前提：目标游戏版本、Mod 前置、当前交付版本，以及需要进入的场景。
- 操作：启用 Mod，执行能触发本次功能的明确动作。
- 预期：可观察的文字、数值、物品去向或角色行为，避免“正常”“没问题”等空泛描述。
- 生命周期：仅在相关时检查禁用/重新启用、切场景、角色重建后是否重复生效或残留。
- 边界：按需求检查空对象、背包满、失败投递或语言切换，不扩大为全游戏测试。
- 存档影响：自定义物品、奖励或持久状态说明实际写入与卸载后果；没有恢复机制时不承诺回滚存档。

每项验收写成“前提 → 操作 → 预期 → 反馈证据”。例如物品悬浮信息功能：进入有物品的背包，将鼠标移到指定物品，检查约定文字和计算结果；反馈该物品、实际文字和截图。公式尚未确认时先查明，不能用示例公式代替用户需求。

多项功能先提供核心行为的验证步骤，再列出其余已实现项。只在存在依赖时等待该步骤反馈；用户尚未验证的项目保留“待用户验证”，不因编译成功自动改为通过。

## 问题反馈与复核

交付 README.md 写明出现问题时需要的最小信息，已有信息直接复用：

- 目标版本：游戏版本、当前 MOD 版本，以及本次交付的 versionId（登记成功后在最终回复提供）；仅在相关时补充前置或其他 MOD 的版本。
- 复现过程：进入的场景、具体操作、预期与实际结果、出现频率；涉及场景切换或重新启用时说明顺序。
- 必要证据：本 MOD 安装目录与文件名、相关画面截图，或触发时间附近的首处异常和调用栈；只请求能帮助区分当前原因的项目，不要求整个存档或完整个人目录。

收到反馈后先核对其对应的交付版本和游戏版本，再区分安装、加载、触发入口、业务效果与生命周期问题。按阶段表检查实际证据；证据不足时给出下一项能区分原因的具体检查，不直接推断为 API 失效或游戏 bug。

同一失败在相同前提下重复且没有新增证据时，停止重复同一尝试，整理已确认事实、已排除原因与缺少的证据，改查相关实现或请求必要信息。修复后给出原复现步骤及直接受影响路径的复核要求，不要求用户重测无关功能。

## 验证状态

按实际证据分别说明，以下状态不互相代替：

| 项目 | 可用依据 | 不能据此确认 |
| --- | --- | --- |
| API 查证 | 当前参考程序集的签名、已阅读的相关实现 | 场景绑定、实际触发与效果 |
| 编译 | 本任务原始 build.ps1 的成功 commandId 与日志 | 已登记、已安装或运行有效 |
| 版本登记 | prepare_delivery 成功后返回的 versionId | 用户已安装或已启用 |
| 安装 | 工作台安装结果或用户反馈，注明来源 | 游戏已加载或功能有效 |
| 加载 | 用户提供的本 MOD 入口日志或游戏显示 | 具体业务已触发或结果正确 |
| 功能与生命周期 | 用户按验收步骤返回的结果、相关日志或截图，注明版本与场景 | 未执行的场景、边界和其他版本兼容性 |

用户只反馈“能用了”时可以记录用户反馈，但不能补写其未提供的测量、截图或边界结论。游戏更新或重新交付后，旧版本的通过结果仅作为参考，受影响项目重新交由用户确认。

分别说明源码实现、API 查证、依赖检查、真实构建命令与结果、打包文件集、prepare_delivery 登记结果、游戏内未验证项。只读任务报告实际完成的定位与证据，不要求打包。

没有成功 commandId 时不声称成功编译；没有 versionId 登记回执时不声称已登记版本；没有游戏内证据时不声称运行效果通过。资料不够时写明缺少的具体 API 或资源，以及下一步验证方式。
