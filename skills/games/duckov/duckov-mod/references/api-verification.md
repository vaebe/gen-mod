# API 查证与版本适配

## 从需求定位到实际符号

1. 列出需要读取或改变的对象，以及触发时机。例如物品悬浮时显示价格，需要物品、悬浮 UI、文本父节点与计算依据。
2. 在 [来源索引](api-sources.md) 中找到相近的上游示例或社区符号；先看已有公开事件或 API 是否可满足需求。
3. 核对用户提供的 ReferenceDirectory、游戏版本说明与已有源码引用。只检查当前功能相关 DLL，不要求安装游戏或遍历整台电脑。
4. 使用已有 ILSpy、IDE 程序集浏览器或用户提供的反编译文本确认类型。没有工具时说明需要的类型导出；不擅自安装工具。
5. 查看目标方法的定义、直接调用者和必要的被调用方法，确认对象有效期、业务条件与副作用。同名方法存在不等于从用户场景可达。

## 每个新增成员需要确认的内容

记录在当前任务说明或相关源码注释中即可，不为每个任务强制建立额外文档：

- 来源：程序集文件、版本信息；可取得时记录 SHA-256。程序集版本可能保持不变，不能单靠它判断游戏版本一致。
- 类型全名、可见性、实例或静态、参数类型和顺序、重载、返回值、必要依赖。
- 事件的委托签名、订阅时机与退订位置；属性是否只读，字段是否可写。
- 调用前提：场景已加载、角色存在、物品归属、游戏数据已初始化等实际保护条件。
- 副作用：修改实例或全局模板、写存档、合并物品、投递仓库、改变 UI 生命周期。
- 证据状态：已核对签名、已阅读相关实现、已编译或用户已验证运行。分别记录，不相互替代。

反编译文本不包含完整 Unity 场景与序列化资源信息；仅有类定义无法确认某个 prefab 已绑定、对象始终存在或 UI 初始化顺序。

## 使用网页示例时

资料中的类型和签名是查找线索。先核对当前 DLL，再摘取最小调用方式，不整段搬运示例。尤其注意：

- NotableAPIs_CN 声明 InstantiateAsync 返回 UniTask<Item>，但示例直接赋给 Item，遗漏了 await。不能照抄这个示例。
- DisplayItemValue 使用 GetTotalRawValue() 的结果再除以 2 显示，不能据此认定该公式等于实际商店售价。
- 文档提到 DialogueUI.DoSubtitle 在历史版本改变可见性；不能把较新版本的 public 方法用于未核对的旧版本。
- 第三方框架的 Identifier、Registry 等接口属于该框架，不是所有 Duckov Mod 都可以直接调用。

## 缺项与升级

编译失败时按缺失类型、成员、重载或运行库分别定位；不要用 catch 返回空值掩盖契约错误。方法变成非公开时，先评估是否有新的公开入口；反射或 Harmony 只有目标签名和调用条件确认后才使用。

用户升级游戏后，重新核对受影响的程序集和调用路径。只有一个目标版本时直接适配该版本；只有用户明确要求多个版本时才设计版本分支，不添加未经验证的候选名称列表。

资料不足时继续完成不依赖缺项的已授权工作，集中说明缺少哪个类型或方法的签名、实现或运行证据。模板能加载或 DLL 能生成都不代表缺失功能已完成。
