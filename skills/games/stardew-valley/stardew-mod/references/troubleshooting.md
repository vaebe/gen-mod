# 排错与验收

先核对玩家使用的游戏、SMAPI、CP/前置与本 MOD 版本，再定位失败阶段。源码检查、结构校验、编译、安装、加载、功能验收分别报告；本技能不授权自动启动游戏或运行测试。

## 先按失败阶段分流

| 现象 | 核对项 | 下一份有区分度的证据 |
| --- | --- | --- |
| SMAPI 未列出 MOD | 实际 Mods 子目录、manifest.json 是否在包根层 | MOD 文件树与 SMAPI 开头的加载/跳过原因 |
| SMAPI 跳过或报前置不符 | MinimumApiVersion、ContentPackFor、Dependencies、重复 UniqueID | 首条 skipped/error，不只截最后一行 |
| C# 加载失败 | EntryDll 与产物名、Mod 子类、运行依赖、程序集版本 | TypeLoad/MissingMethod/缺依赖异常及调用栈 |
| CP 包加载但无效果 | Action、Target、When、FromFile、目标实际是否被游戏读取 | patch summary 中对应 LogName 状态 |
| 数据导出正确但游戏无变化 | 场景、缓存、实例旧值、当前使用的条目 | 真正触发步骤与导出目标字段 |
| 图片错位/透明异常 | 图集布局、像素坐标、PatchMode、使用中的表情或动画 | 源图尺寸、补丁区域与实际画面 |
| 只在多人/换存档出错 | 主机执行者、分屏缓存、ReturnedToTitle 清理 | 主机/客机各自日志与重现顺序 |
| 资源在开发机存在但安装后丢失 | ResourceManifest、package 实际文件、target 映射 | 包内路径与代码/JSON 引用对照 |

## Content Patcher 控制台

这些命令由玩家在 SMAPI 控制台执行，先看当前版本 `patch help`：

- `patch summary`：看 loaded、conditions、applied。条件不匹配和资产尚未读取是不同原因。
- `patch export Data/Objects`：示例，导出补丁后的资产，检查目标键/字段；不用于写回游戏原文件。
- `patch reload <内容包UniqueID>`：修改包后重新加载，再触发目标场景；不宣称所有游戏实例都会即时更新。

资料核对日期 2026-11-06。其余参数、输出位置和高级命令查[作者排错指南](https://github.com/Pathoschild/StardewMods/blob/develop/ContentPatcher/docs/author-guide/troubleshooting.md)。未经玩家同意，不上传日志、存档或文件到在线验证网站。

先从 summary 确定失败补丁，再查具体源文件；多个包冲突时对照最终导出结果、manifest 依赖与补丁顺序。只要求调整确实有顺序依赖的项，不通过重命名文件夹碰运气。

## 按功能写验收步骤

每条用“前提 → 操作 → 可观察预期 → 反馈证据”：

| 功能 | 最小验收 | 直接相关边界 |
| --- | --- | --- |
| 对话 | 在确实选择该键的日期/关系与 NPC 交谈，显示约定文本 | 关闭配置、语言切换、被其他条件覆盖 |
| 售价 | 对指定 ID 与品质执行约定买卖行为，得到预期数额 | 购买/售出差异、职业加成 |
| 贴图 | 打开使用该区域的界面，看到实际资源 | 其他表情/动画、透明像素、季节 |
| 快捷键 | 自由操作时按配置键，只执行一次 | 菜单、标题界面、按键冲突 |
| 新物品 | 从实现的获得途径取得，图片/描述/功能正确 | 背包满、保存重读、卸载说明 |
| 持久进度 | 达成条件并保存，重读后保持 | 换存档不串数据、客机不重复执行 |

只有用户确实反馈的场景标注已验证，其余保留待验证。反馈不足时请求当前版本、操作步骤、预期与实际、SMAPI 首条相关异常；已有证据直接复用。不把“能编译”或“玩家说加载了”提升为所有功能通过。
