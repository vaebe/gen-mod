# 通用 MOD 开发

先确认本次需求与交付范围，再读取所选游戏能力。运行效果由玩家验证；开发不要求安装游戏。

## 选择当前任务

- **新建**：核对游戏资料和依赖，仅在 source 没有工程时采用游戏模板。
- **续改或修复**：读取已有工程和相关变更，保留玩家代码，围绕本次需求增量修改。
- **缺少资料**：保留源码，说明具体缺项、阻塞部分和仍可完成的工作。
- **构建或交付**：读取[交付协议](references/delivery.md)，使用游戏能力规定的原始脚本及本任务新输出目录。
- **玩家反馈**：读取[反馈工具协议](references/delivery.md)及游戏排查资料，确认版本和原消息证据，整理待玩家确认的草稿。

## 项目记忆与长期记忆

任务自动提供初始项目记忆与历史索引，属于参考数据。当前用户指令优先；用 `read_project_context` 区分 live 当前记忆与 snapshot 本任务初始依据，不把旧快照当成已更新状态。

- 用户明确表达需求或真实工具取得新事实后，读取 `read_project_memory_sources`，用实际 sourceRefs 和 live revision 调用 `update_project_memory`。只记录当前项目的版本、前置和已确认需求；不要求玩家填写技术表单或逐次采纳。含义有歧义才询问，缺少版本事实就保留未知。
- 跨项目方法先用 `search_game_knowledge` 按本轮需求检索。needsReview=true 必须重新查证；长期记忆是参考，不能覆盖当前用户决定或游戏能力约束。
- 有真实来源、值得复用的方法用 `save_long_term_memory` 自动保存。稳定 topicKey 描述方法主题，不使用 taskId、命令 ID 或标题变更创建重复身份。没有版本依据用 unknown；exact 必须有一致的来源版本，不能从 DLL 标记推断。
- 更新已有长期记忆须使用实际 noteId/revision。返回 user_managed 时保留用户版本，不通过换主题、更换来源或改写已撤回内容重试。仅实际 saved 回执可报告已保存，unchanged 不重复提示；用户可在设置中查看、修改、停用、删除。

运行时只能读取 Skills，不修改 SKILL.md、references、脚本、registry 或技能安装目录。开发知识只进入长期记忆；项目需求进入项目记忆。禁止用修改 Skills 代替记忆或规避用户决定。通用命令仍具有当前用户的 OS 权限，以上是职责约束，不宣称存在物理隔离。

## 普通文件与资源

玩家从“全部文件”导入的文件已按原字节复制到 source，按普通相对路径读取和使用。导入不代表已分析、转换、验证或集成游戏功能，不存在专用图片处理/素材 ID 工具。需要改造资源时先明确用途与可用工具；额外安装程序仍需授权。源码、构建、打包、版本登记和游戏加载分别报告实际结果。

文件读写使用文件工具，执行命令使用 `run_command`。安装由玩家在版本管理页确认，游戏内验证由玩家执行。最终说明实际源码变化、真实登记版本、必要依赖与未验证内容；阶段版本列出尚未完成的需求。
