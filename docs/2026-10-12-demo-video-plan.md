# GenMod 功能介绍与小地图 MOD 演示录制计划

**目标：** 使用现有“小地图”项目，通过 GenMod 将小地图边框改为绿色，记录需求、生成、安装与游戏内效果，剪成一条约 90 秒的功能介绍与操作演示视频。

**执行方式：** 在当前会话逐阶段操作，使用 OBS 录制真实应用和游戏画面。先准备录制环境与修改前素材，再发送修改需求；生成过程在后期加速，其他关键操作和效果展示保留正常速度。

**依据：** 用户已指定安装 OBS、使用现有小地图项目、修改边框为绿色，并要求先写计划；随后明确成片总长约 90 秒，MOD 生成过程加速。本轮仅编写计划；OBS 安装完成且用户确认计划后开始执行。

## 范围与交付

- 一条视频合并功能介绍与 MOD 演示：横屏 1920×1080，目标总长约 90 秒（85～95 秒）。
- 保留原始录屏、旁白稿、字幕和最终视频，统一保存到 `output/demo-video/`。
- 本次仅改变小地图边框颜色，建议绿色为 `#22C55E`；保持边框形状、粗细、地图尺寸、缩放、图标、按键、显示条件及其他行为不变。
- 不修改 GenMod 应用代码，不提交、不推送、不发布，不删除已有项目或版本，不安装额外依赖。
- 配置已保存的模型可用于本次真实生成；生成可能消耗服务商额度。录制不展示 API Key，不打开私人聊天或无关窗口。
- 安装前核对真实游戏目录、覆盖清单及恢复方式。无法确认旧版本能恢复时，暂停覆盖，先说明情况。
- 游戏内效果以真实运行结果为准；编译成功、版本登记或聊天回复不能代替游戏内验证。

## 阶段 1：环境和基线准备

- [ ] 用户完成 OBS 安装，并确认本计划。
- [ ] 查看 OBS、GenMod 和游戏可用状态，确认当前小地图项目与会话。
- [ ] 从应用中确认当前版本、安装状态和游戏位置，保留旧版本标识与安装信息。
- [ ] 确认生成使用的模型及编译资料可用，不展示或重新填写密钥。
- [ ] 进入游戏，确认当前小地图能显示，记录原边框颜色；如果已经是绿色，先重新确定能形成对比的演示方式，不擅自改成其他颜色。
- [ ] 选择一个可重复进入、地图和角色图标容易看清的场景，录下修改前画面。

**完成条件：** 修改前效果已实际确认，旧版本已保留，生成与游戏演示条件齐备。

## 阶段 2：OBS 配置与样片

- [ ] 创建本次专用场景集合，保留用户已有录制配置。
- [ ] 设置“应用演示”场景捕获 GenMod，“游戏效果”场景捕获游戏；优先只捕获目标窗口。
- [ ] 输出设为 1920×1080、30 fps；采用现有可用编码器，先录制 MKV，再转封装为 MP4。
- [ ] 录屏目录设为本仓库 `output/demo-video/raw/`。开始前检查是否存在同名文件，避免覆盖。
- [ ] 固定 GenMod 窗口大小，保证需求、生成状态及版本信息可读。
- [ ] 默认不录麦克风，旁白后期单独处理；如用户希望真人配音，由用户录制声音。
- [ ] 录制并回看约 20 秒样片，检查黑屏、画面裁切、文字清晰度和声音。合格后正式录制。

**完成条件：** 应用和游戏捕获均有效，样片清楚可读。

## 阶段 3：录制真实生成过程

- [ ] 开始录制，展示小地图项目和已有会话，保留操作前后各 2 秒停顿。
- [ ] 输入并展示以下完整需求，再发送：

> 请在现有小地图 MOD 的基础上，只把小地图边框颜色改为绿色（#22C55E）。保持边框形状和粗细、地图大小和缩放、角色及其他图标、按键、显示条件与其他行为不变。先找到现有边框绘制位置，再做最小修改，使用项目现有编译方式生成一个新版本，并说明修改文件和编译结果。

- [ ] 录下实际生成过程；查看必要工具记录和编译结果，避免频繁展开无关内容。
- [ ] 如生成失败，记录错误并先排查与本次修改直接相关的问题；不把失败回复剪成成功结果，不扩大修改范围。
- [ ] 确认本任务实际编译成功且新版本已登记，查看交付文件与版本详情。
- [ ] 核对源码差异，仅边框颜色及其直接必要实现发生改变；发现无关修改时先纠正，再继续安装。
- [ ] 保留完整原始录屏。成片中的等待可以剪切或加速，字幕标明“等待片段已剪辑”或“生成过程已加速”，耗时采用本次真实记录。

**完成条件：** 生成的新版本包含目标修改，有真实编译与版本记录，修改范围核对完成。

## 阶段 4：安装与游戏效果

- [ ] 根据 MOD 的加载方式退出游戏或回到允许重新加载的状态，避免复制成功但仍运行旧程序集。
- [ ] 在版本管理中选择本次版本，查看安装路径、映射和覆盖清单；确认对应现有小地图 MOD。
- [ ] 确认旧版本恢复方式可用后执行安装，记录实际结果。
- [ ] 进入游戏并启用或重新加载 MOD，回到阶段 1 的同一场景。
- [ ] 录下绿色边框的近景和正常游戏操作画面，核对边框粗细、地图尺寸、图标与按键行为仍符合原功能。
- [ ] 拍摄修改前后对比。若效果未生效，回到加载、安装和绘制路径排查，不声称演示完成。

**完成条件：** 游戏内真实显示绿色边框，目标修改有效，关键原行为未出现可见变化。

## 阶段 5：补拍与剪辑

### 合并成片：约 90 秒

| 时间 | 画面 | 旁白方向 |
| --- | --- | --- |
| 0～8 秒 | 原边框与绿色边框对比 | “用一句中文需求，把小地图边框改成绿色。” |
| 8～20 秒 | GenMod 工作台与现有小地图项目 | “GenMod 是一个本地 AI MOD 工作台，可以通过对话修改代码、编译和生成版本。” |
| 20～33 秒 | 输入并发送边框修改需求 | “这次只修改边框颜色，保留地图和图标的原有行为。” |
| 33～53 秒 | 加速展示真实生成、编译与交付 | “AI 根据现有项目完成修改，调用编译流程，生成新版本。” |
| 53～63 秒 | 新版本与交付文件 | “查看本次版本与交付文件，也可以导出 ZIP。” |
| 63～73 秒 | 安装预览、确认与结果 | “确认目标目录和覆盖文件，安装新版本。” |
| 73～87 秒 | 游戏内绿色边框、同场景前后对比 | “进入游戏，边框已经变为绿色，地图和图标保持原样。” |
| 87～90 秒 | 游戏效果定格与 GenMod 名称 | “GenMod，让 MOD 创作从一句需求开始。” |

生成片段按实际原始时长计算加速倍率，将其压缩到约 20 秒；角标显示“生成过程已加速”，并注明真实耗时。发送需求、编译成功与新版本出现等关键节点适当停留；较长静止等待可剪掉并标注。游戏加载等待不计入正常速度展示，可剪切处理。旁白中的成功描述仅在实际验证后使用。

- [ ] 补拍必要的工作台、文件和版本界面镜头，不重新生成同一修改。
- [ ] 按真实素材完善旁白和字幕，使用实际版本、耗时与结果。
- [ ] 检查本机已有剪辑、转封装与音频工具；优先使用可用工具。需要新增软件或依赖时先说明并确认。
- [ ] 若没有可用配音工具，先交付带字幕版本及完整旁白稿；不把配音列为已经完成。
- [ ] 将素材剪成一条约 90 秒视频，等待片段明确标记剪辑或加速，保持需求、生成版本和游戏效果对应同一次操作。
