## 任务 2：重组入口与单一资料职责

- [ ] 描述采用“做什么 + 何时使用”，保留中文与实际游戏关键词；registry 同步，避免塞进完整执行步骤。
- [ ] 通用入口收敛为任务类型、现有工程续改、工具与交付入口；原生已校验的字段规则只在交付协议维护。
- [ ] Duckov 入口采用以下路由结构，并保留原始必需脚本的不可替代性：

```markdown
## 选择当前任务
- 新建或续改：读取来源与依赖，检查已有工程后选择实现入口。
- 新 API 或版本不符：读取 API 查证，核对当前签名与调用条件。
- UI、资源或补丁：只读取对应专题。
- 构建与交付：读取交付协议，调用本能力原始构建脚本。
- 用户反馈：读取排查资料，核对版本与场景后整理验证结论。
```

- [ ] 完整构建参数示例归入 dependencies 的构建段；入口链接到它。通用工具字段留在 common delivery，游戏专属目标路径留在 Duckov。
