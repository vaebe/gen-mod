# 领域文档

本仓库采用 single-context 布局。

## 探索代码前

- 阅读根目录 `GLOSSARY.md`。
- 阅读 `docs/adr/` 中与当前工作相关的架构决策。

文件或目录不存在时直接继续，不将缺失作为问题，
也不主动建议预先创建。
由 domain-modeling 技能在术语或决策明确后按需创建。

## 文件布局

- `GLOSSARY.md`：共享领域术语表。
- `docs/adr/NNNN-<decision>.md`：架构决策记录。

## 使用统一术语

在任务标题、重构建议、假设及测试名称中引用领域概念时，
使用术语表定义的名称，避免使用其中明确排除的同义词。

需要的概念未被收录时，先检查是否引入了项目不用的说法；
确认存在术语缺口后，再交由 domain-modeling 处理。

## 显式指出决策冲突

建议与现有 ADR 冲突时，明确指出对应 ADR、冲突内容，
以及重新讨论该决策的理由，不静默覆盖已有决策。
